# 每日减脂

一个自用的「训练 + 减脂餐」每日计划应用。填一次身体数据，它给你：

- 每天的热量上限、蛋白/碳水/脂肪目标
- 早/午/加餐/晚四餐的具体菜和克数，可以单换某一道
- 今天该练什么，每个动作几组几次，带组间休息计时器
- 体重趋势、打卡日历

因为你的手机是 iPhone，而 Windows 上没法打包 iOS 安装包，所以这是一个 **PWA**：用 Safari 打开、
「添加到主屏幕」之后，就有独立图标、全屏运行、断网可用，和普通 App 用起来没区别，也不需要服务器。
数据全部存在手机本地，没有账号、没有上传。将来如果要做成上架的原生 App，这套代码可以直接用
Capacitor 打包，不用重写。

## 目录结构

```
index.html            入口
manifest.webmanifest  PWA 配置（名称、图标、全屏模式）
sw.js                 离线缓存
css/styles.css        全部样式
js/app.js             路由、事件分发、备份导入导出
js/views.js           五个页面 + 首次设置页的界面
js/store.js           状态与本地存储（localStorage）
js/nutrition.js       热量目标推算、餐单自动生成与配平
js/data/              食材库、餐单库、动作库、训练计划
tests/smoke.mjs       数据与算法的冒烟测试
tools/                图标生成、界面截图（开发用，不参与运行）
```

零依赖、无构建步骤。改完文件刷新页面就是最新版本。

## 本地预览

在 `outputs/fitcut-app` 目录下起一个静态服务器（不要直接双击 index.html，ES 模块和离线缓存需要 http 环境）：

```powershell
python -m http.server 8123 --bind 127.0.0.1
```

然后浏览器打开 <http://127.0.0.1:8123/>。

## 装到 iPhone 上

离线缓存要求 HTTPS，所以要把这几个文件挂到一个静态托管上（都免费）：

1. **GitHub Pages**：新建一个仓库，把这几个文件和目录传上去 → Settings → Pages → 选 `main` 分支根目录 → 得到 `https://<你的用户名>.github.io/<仓库名>/`。
2. 或者 **Cloudflare Pages**：把文件夹拖进去，几十秒就有地址。

然后在 iPhone 上：

1. 用 **Safari** 打开那个网址（注意必须是 Safari，Chrome 装不了主屏应用）
2. 点底部「分享」→「添加到主屏幕」
3. 以后从桌面图标直接打开，全屏运行，飞行模式也能用

路径全部是相对路径，放在子目录里也能正常工作。

## 数据与备份

- 数据存在这个应用的本地存储里，换手机、清理 Safari 网站数据、卸载重装都会丢。
- 「我的 → 数据备份 → 导出备份」会生成一个 JSON 文件存到 iPhone 的「文件」里，换设备时用「导入备份」恢复。
- 建议每周导一次。

## 想改点什么

| 想改的东西 | 改哪里 |
| --- | --- |
| 食材营养值、加新食材 | `js/data/ingredients.js`（每 100g 的热量/蛋白/碳水/脂肪） |
| 加减一道菜 | `js/data/dishes.js`，写成「食材 + 克数」，营养值由程序自动算 |
| 加减动作、改动作提示 | `js/data/exercises.js` |
| 训练计划、组数次数 | `js/data/templates.js` |
| 热量公式、安全下限、四餐比例 | `js/nutrition.js`（比例在 `dishes.js` 的 `MEAL_SPLIT`） |
| 配色、字号 | `css/styles.css` 顶部的 CSS 变量 |

改完记得跑一下测试，防止加菜时引用了不存在的食材：

```powershell
node tests/smoke.mjs
```

## 已知限制

- 食材营养值是常见参考值的取整（中国食物成分表 / USDA），不同品牌和做法有 10%~20% 浮动，够日常规划用，不当作医学依据。
- 菜谱是固定的家常搭配，不是按你冰箱里的东西现算的。
- 没有账号和多设备同步；要同步得自己加后端。
- iOS 的 PWA 不支持后台推送和震动反馈，休息计时器切到后台可能不准。
- 餐单只在「我的」里改身体数据时会重排接下来 7 天，历史记录保持原样，不会被覆盖。
